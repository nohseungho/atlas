# 무료 TOP5와 제작자료 준비

`/atlas/unified-publish`: 오늘 자료 업데이트 → 국내·해외 TOP5 → 선택 → 블로그 준비 또는 쇼핑쇼츠 준비.

이 버전의 통합 API는 실제 발행 요청에 항상 403을 반환한다. 발행 provider를 호출하는 경로가 없다. 기존 다른 발행 화면은 이 작업의 대상이 아니며 테스트 중 호출하지 않는다. 유료 AI·API·이미지 생성·새 키는 사용하지 않는다.

## 공개 출처

- 국내 최신 할인 후보: `https://www.ppomppu.co.kr/rss.php?id=ppomppu`
- 국내 인기 목록: `https://www.ppomppu.co.kr/zboard/zboard.php?id=ppomppu&hotlist_flag=999`
- 국내 추천 수: 개별 글의 `vote_list_btn_txt` / `vote_anti_list_btn_txt`에 명시된 값만 읽는다. 조회 수를 인기 추천 수로 바꾸지 않는다.
- 해외 최신 후보: `https://www.dealnews.com/?rss=1`
- 해외 인기 목록: `https://www.dealnews.com/?rss=1&sort=hotness`
- [DealNews 공식 피드 안내](https://www.dealnews.com/pages/rss.html)

최근 72시간 이내 게시물에서 후보군을 모은 뒤 선별한다. 페이지당 최대 2MB, 요청당 10초, 국내 상세페이지 최대 동시 4개로 제한한다. 차단 우회나 로그인 수집은 하지 않는다. 해외 피드의 sale, up-to, from-price, 행사 모음은 개별 제품으로 추천하지 않는다. 원본 출처 링크와 referral 파라미터는 보존한다.

## 내부 선별 규칙

각 항목을 0–100으로 평가하고 **인기 40% + 할인·가격 30% + 실용성 20% + 출처·최신성 10%**로 합산한다. 화면에는 점수나 내부 상태를 표시하지 않는다.

| 항목 | 실제 사용하는 근거 |
| --- | --- |
| 인기 | 출처의 인기 목록 포함: 100. 명시된 추천−다른 의견: 순추천 1개당 5, 최대 100. 순추천 5개 이상부터 인기 배지 허용. 시장 전체 판매 순위라는 뜻은 아님. |
| 할인·가격 | 명시된 할인율 × 2, 최대 100. 또는 같은 제품의 확인된 현재가·명시된 정상가로 산술 계산. 쿠폰·추가·최대 할인율은 확정 할인율로 사용하지 않음. 절약액만으로 정상가를 역산하지 않음. |
| 실용성 | 제목의 용량·구성 확인: 50. 명시된 다개입 생활 소모품: 100. 제품 품질이나 장기 사용 경험을 추정하지 않음. |
| 출처·최신성 | 정해진 공개 출처의 유효한 24시간 이내 확인 자료: 60 + 게시 후 72시간에 걸쳐 40→0. 출처와 시각이 없거나 오래된 자료는 제외. |

인기와 실제 할인 근거가 함께 있는 제품을 우선한다. 이후 인기 또는 출처의 편집자 선정 근거가 있는 제품을 배치한다. **할인만 있는 약한 후보는 1–3번 슬롯에 들어갈 수 없다.** 근거가 부족하면 슬롯을 비워 두며 다섯 제품을 꾸며 채우지 않는다. 대표 배지는 인기템 / 쟁여둘 때 / 가성비 / 지금 할인 중 근거가 허용하는 하나만 사용한다.

동일 모델·브랜드, GTIN, 정규화한 제품명, 정규화한 출처·상품 URL로 중복을 묶는다. 판매처 접두사, 가격·배송 접미사, 추적 파라미터 차이를 제거한다. ATLAS의 국내 원고, 해외 기사, 발행 작업, 통합 결과, 확인된 외부 공개 글의 제품을 제외한다. `publishing`/`needs_reconciliation`의 불명확한 시도도 제외한다. 식별 정보가 없는 서로 다른 언어의 별칭을 동일 제품으로 추측하지 않는다.

## 자료·이미지

블로그와 쇼츠를 각각 준비할 수 있고, 둘은 동일 제품·근거 스냅샷·확인 날짜를 공유한다. 재시도는 이미 준비된 자료를 덮어쓰지 않는다. 새로운 수집 시각의 자료로 다시 준비하면 이전 편집 원고는 `archives`에 보존하고 ‘저장한 자료·발행 결과’에서 다시 볼 수 있다.

국내는 정책의 수호 마스터, 해외는 정책의 미지 마스터를 자동 연결한다. 경로와 캐릭터를 별도 복제한 설정으로 관리하지 않고 `character-channel-policy.js`에서 읽는다. 미지 마스터는 로컬 원고 미리보기와 쇼츠 이미지 저장소에 자동 전달한다. 진행자 이미지이며 실제 제품 사진으로 표시하지 않는다. Blogger 공개 이미지 호스팅은 실제 발행을 재개할 때 별도로 검증해야 한다.

쇼츠 스튜디오는 기존 PhotoCardStudio와 IndexedDB 저장소를 재사용한다. 실제 동영상 렌더링·플랫폼 업로드는 범위에서 제외한다. Naver 브라우저 프로필 설정은 변경하지 않는다.

## 저장·복구

`.atlas-data/unified/state.json`은 Git 제외 대상이다. 원자적 파일 교체와 프로세스 간 잠금으로 저장한다. `results[channel][productId]`에 확인된 발행 URL·외부 ID·제품 근거를 보존하고, 복구 이벤트를 `history`에 기록한다.

‘발행 결과 다시 확인’은 Blogger 공개 글 목록 또는 Naver 공개 RSS를 **읽기만** 한다. 저장된 외부 ID/URL, 또는 제목+제품 출처+시도 이후 발행 날짜가 유일하게 일치할 때만 결과를 복구한다. 공개 글 관측 기록은 RSS에서 오래된 글이 빠져도 유지한다. 한 채널의 조회 실패가 다른 채널의 성공이나 기존 URL을 지우지 않는다. 일치 없음·복수 일치·로그인 만료·RSS 범위 밖 글은 잠금을 유지하며 자동 재발행하지 않는다. 보호 글 `224407589323`은 복구 결과로도 인정하지 않는다.

프로세스가 파일 잠금 보유 중 강제 종료된 경우, 남은 `write.lock`은 자동 제거하지 않는다. 실제 작업과 공개 결과를 대조한 뒤 운영자가 복구해야 한다. 파일 저장소는 한 PC 운영용이다.

## 검증

- `npm run unified:verify`: 점수·근거 누락·할인 추정 방지·중복·캐릭터·개별 준비·원고 보존·부분 실패·결과 복구.
- 관련 파일 ESLint, `npm run build`.
- `node scripts/atlas-unified-browser-check.mjs`: localhost:3002, 실제 무료 수집, 상세보기, 개별 준비, 미지 이미지 전달, 모바일 가로 넘침, 실제 발행 차단. Naver/Blogger 발행 요청은 브라우저에서 차단한다.
